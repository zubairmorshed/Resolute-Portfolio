Bug OWQA-12

The temperature field accepts unrealistic values (e.g., 9999)

h3. Temperature field accepts extremely large numeric values outside the expected LLM parameter range.

h3. *Environment*

* Open WebUI (local instance)
* Model: llama3.1:latest
* Browser: Chrome / Edge
* OS: Windows

h3. *Severity:* Low

h3. *Priority:* Medium

h3. *Precondition*

User is logged into Open WebUI.

h3. *Steps to Reproduce*

# Go to *Settings → Models*
# Select the default model (e.g., llama3.1:latest)
# Locate the *Temperature* field
# Enter a value such as *9999* or *-500*
# Click outside the field or save settings

h3. *Expected Result*

* Temperature should be restricted to a reasonable range (e.g., 0.0 to 2.0)
* UI should prevent unrealistic values
* Validation message should appear if the value is out of range

h3. *Actual Result*

* The field accepts extremely large values (e.g., 9999)
* No validation or warning is shown
* Settings appear to save successfully

h3. *Impact*

* Users may unintentionally break model behavior
* Poor UX due to lack of validation
* Inconsistent with typical LLM parameter ranges

Bug OWQA-11

No confirmation message after changing settings

Settings changes do not display any confirmation message, leaving the user unsure if changes were saved.

h3. *Environment*

* Open WebUI (local instance)
* Model: llama3.1:latest
* Browser: Chrome / Edge
* OS: Windows

h3. *Severity:* Medium

h3. *Precondition*

User is logged into Open WebUI.

h3. *Steps to Reproduce*

# Go to *Settings → Models*
# Change any parameter (Temperature, Top‑K, Max Tokens, etc.)
# Click outside the field or navigate away
# Observe the UI

h3. *Expected Result*

* A confirmation message should appear, such as: *“Settings saved successfully.”*
* User should receive clear feedback

h3. *Actual Result*

* No confirmation message appears
* No visual feedback is provided
* User cannot tell if the change was saved

h3. *Impact*

* Causes confusion
* Users may repeat actions unnecessarily
* Reduces trust in the settings panel
